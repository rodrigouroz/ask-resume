# Resume and CV principles

Reviewed on 2026-08-27. These rules shape three projections of the same verified facts: the rich accessible website, the current visual CV, and a linear ATS-oriented application resume.

## Content

- Put professional experience before personal projects and lead each role with scope, contribution, and outcome.
- Use concise, specific language and quantify impact only when the evidence supports the number.
- Tailoring may select, shorten, and reorder verified facts for a role. It must never create a metric, responsibility, technology, employer, or outcome.
- Keep a short profile to one page when it remains legible and complete. Allow up to two pages when shortening would remove relevant experience.
- Separate employers, clients, and independent work so the reader cannot infer a relationship that did not exist.
- Mark fictional demonstrations explicitly and never use real commercial brands for dummy employment.

## ATS projection

- Use a single logical reading order, standard headings, real text, descriptive links, and no meaning carried only by color or layout.
- Avoid columns, text boxes, charts, decorative icons, and logos in the ATS artifact.
- Keep dates, organization names, roles, and skill terms explicit. Do not keyword-stuff or hide text.
- Treat parsing as a compatibility target, not a guarantee: vendors support common document formats but parsing can still fail on complex layouts or image-only content.

## Web and PDF accessibility

- Preserve semantic headings, keyboard access, visible focus, mobile target sizes, language metadata, alt text, sufficient contrast, and reduced-motion behavior.
- The PDF must contain extractable text, working links, coherent reading order, document metadata, and tags. Render every page for visual inspection.
- SEO output comes from the active profile: canonical URL, social preview, sitemap, robots file, and `ProfilePage` structured data must agree.

## Sources

- [Silver Interview Ready — CV checklist](https://docs.silver.dev/interview-ready/consiguiendo-entrevistas/preparando-el-cv#cv-checklist): practical developer-CV review checklist. Useful as a quality source, but not copied into the public evidence corpus.
- [Harvard Career Services — Create impactful resumes and cover letters](https://careerservices.fas.harvard.edu/resources/hes-create-impactful-resumes-and-cover-letters/): concise, audience-focused writing and accomplishment framing.
- [MIT CAPD — Resumes: Writing about your skills](https://capd.mit.edu/resources/resumes-writing-about-your-skills/): evidence-led skill and accomplishment language.
- [MIT CAPD — Make your resume ATS-friendly](https://capd.mit.edu/resources/make-your-resume-ats-friendly/): simple structure, standard headings, and keyword fidelity.
- [Stanford Career Education — Resume and cover letter examples](https://careered.stanford.edu/sites/g/files/sbiybj22801/files/media/file/resume-and-cover-letter-examples.pdf): examples and editorial patterns, not a visual template mandate.
- [Greenhouse — Unsuccessful resume parse](https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse): concrete examples of parsing limitations.
- [W3C — Web Content Accessibility Guidelines](https://www.w3.org/WAI/standards-guidelines/wcag/): accessibility baseline for the online CV.
- [W3C PDF3 — Correct reading order](https://www.w3.org/WAI/WCAG21/Techniques/pdf/PDF3): reading-order guidance for tagged PDF documents.
- [Google Search — ProfilePage structured data](https://developers.google.com/search/docs/appearance/structured-data/profile-page): profile-page SEO semantics and validation.

These sources guide presentation and review. Biography claims still require explicit approved evidence in `profile/evidence.json`.
